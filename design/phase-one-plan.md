# 第一部分开发进度：租户、系统、管理员与审计

更新日期：2026-09-14。Owner 已批准七表设计并授权开发；本次追加本地登录和独立前端初始化，系统密钥简化为固定 Token，不做轮换。

## 目标与边界

本期管理流程：离线初始化首个超管 → 管理员登录 → 创建租户和后台用户 → 分配租户管理员 → 创建租户内系统及唯一账号 → 租户管理员生成固定 Token → 系统身份验证 → 查询管理审计。

- 每个系统唯一归属一个租户；用户与租户多对多。
- 后台只有平台超管与租户管理员；后台用户、系统调用账号和业务系统内的用户相互独立。
- 每账号至多一把有效固定 Token，不自动到期、不轮换。Token 只能由所属租户的有效管理员创建；平台超管需要该租户成员身份才可签发。
- PostgreSQL 保存管理状态与审计；SpiceDB 资源模型、关系写入、授权检查与可靠同步属于第二部分，本次不实现 outbox 或授权镜像。
- 前端本次完成登录、身份恢复、退出和账户概览；完整管理页面是下一批前端工作。

## 实现约定

领域与应用不依赖 Gin/GORM/Authzed；HTTP 做协议转换。管理用例共用授权范围、版本检查和事务审计，避免每个 Handler 重写规则。一期所有管理写事务共用 PostgreSQL advisory lock，适用于当前较小管理写入量；只读事务使用 Repeatable Read，保证列表和计数同一快照。后续吞吐优化需整体设计锁顺序。

成功变更和成功审计同事务；失败不转为成功，独立记录已验证的操作者与安全失败分类，日志不记录秘密。固定 Token 的明文仅在创建结果返回；查询只返回元数据，吊销不会被上层恢复复活。

登录 JWT 具有有限有效期。前端退出清理当前标签页会话，本期没有 refresh token 或跨设备会话撤销；用户停用会在后续请求中生效。固定系统 Token 与管理员 JWT 的生命周期不同。

## 验收重点

1. 空用户库才能初始化超管；错误密码、未知用户、停用用户不允许登录/管理，最后超管不能被停用或降级。
2. 一人可管理多个租户；管理员不能读取其他租户的详情、列表、计数、系统、Token 或审计。
3. 创建系统同时创建唯一账号，不自动签发；超管无成员关系不能签发，成员有效性在写事务中复查。
4. 并发签发最多成功一次；吊销与账号/系统/租户停用影响后续身份探测，无允许缓存。
5. 更新使用 version；审计插入失败回滚管理变更，DTO/审计不含密码、JWT、Token 或摘要。
6. 前端正确登录、错误提示一次、loading/防重复、刷新恢复、退出、401 和迟到响应处理；桌面和窄屏均可操作。
7. Go 测试/vet/构建、前端 pnpm check、文档链接/YAML/OpenAPI/SQL 检查。原生 PostgreSQL 与模拟测试结果分别记录。
